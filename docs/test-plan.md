## 一、测试策略概述

### 测试范围

MVP 包含以下核心模块：
1. **用户系统**：微信登录、个人信息、设置管理
2. **任务卡片**：创建、编辑、完成、删除、优先级管理
3. **AI 对话**：晨启对话、晚审对话、思维转换
4. **金币系统**：赚取、余额管理
5. **每日记录**：日志查看、完成率统计
6. **小程序前端**：页面渲染、交互、通知

### 测试类型

| 类型 | 说明 | 工具 |
|------|------|------|
| 单元测试 | 后端各模块独立测试 | pytest |
| API 测试 | FastAPI 接口测试 | pytest + httpx |
| 集成测试 | 前后端联调 + AI 调用 | 手工 + 微信开发者工具 |
| UI 测试 | 小程序页面和交互 | 微信开发者工具 |
| AI 质量测试 | Prompt 输出质量评估 | 人工评审 |
| 安全测试 | 接口鉴权、数据隔离 | 手工 + 脚本 |
| 性能测试 | API 响应时间、并发 | locust / ab |

### 测试环境

| 环境 | 说明 |
|------|------|
| 本地开发 | SQLite + FastAPI dev server |
| 测试环境 | 微信开发者工具 + 测试后端 |
| 生产环境 | 阿里云服务器 / 微信云开发 |

## 五、AI 质量评估

### 评估维度

对 AI 生成的内容按以下维度打分（1-5 分）：

| 维度 | 说明 | 最低要求 |
|------|------|---------|
| **温度感** | 像朋友说话，不像机器或命令 | >= 4 |
| **具体性** | 内容具体，与用户任务相关，非泛泛鸡汤 | >= 4 |
| **长度控制** | 控制在 150 字以内，不啰嗦 | >= 3 |
| **正向性** | 不批评、不制造内疚、不说教 | >= 5 (必须) |
| **实用性** | 推荐的任务合理，建议可执行 | >= 3 |
| **创意性** | 思维转换有新鲜感，不重复 | >= 3 |

### 评估方法

1. 准备 10 组不同的用户画像（任务数量、打卡天数、完成率各异）
2. 每组生成 3 次晨启 + 3 次晚审 + 3 次思维转换
3. 由 2-3 人独立打分，取平均值
4. 低于最低要求的场景需调整 Prompt

### 重点检查场景

| 场景 | 检查点 |
|------|--------|
| 用户连续 3 天未打卡后回归 | AI 是否说"没事，回来就行"而非指责 |
| 用户当天全部任务未完成 | AI 是否温和，不制造压力 |
| 用户只有 1 个很大的任务 | AI 是否建议拆解 |
| 用户任务连续 3 天被推迟 | AI 是否识别拖延并给出针对性转换 |
| 新用户首次使用 | AI 是否友好引导，不显得冰冷 |

## 六、性能测试

### 响应时间要求

| 接口类型 | 目标响应时间 |
|----------|------------|
| 用户登录 | < 1s |
| 卡片 CRUD | < 500ms |
| AI 晨启/晚审 | < 5s（含 AI API 调用） |
| 思维转换生成 | < 3s |
| 每日记录查询 | < 500ms |

### 并发测试

| 场景 | 目标 |
|------|------|
| 10 用户同时请求晨启 | 所有请求成功，响应 < 8s |
| 50 用户同时创建任务 | 所有请求成功，响应 < 1s |
| 100 用户同时登录 | 所有请求成功，响应 < 2s |

### 数据库容量

| 场景 | 指标 |
|------|------|
| 1000 用户各 100 张卡片 | 查询响应 < 100ms |
| 单用户 1 年日志（365 条） | 查询响应 < 200ms |

## 七、回归测试清单

每次发版前必须通过以下核心路径：

```
[ ] 1. 微信登录 → 获取用户信息 → 正确返回
[ ] 2. 创建任务卡片 → 列表中可见
[ ] 3. 完成任务 → 金币正确增加
[ ] 4. 请求晨启对话 → AI 返回有效内容
[ ] 5. 请求晚审对话 → 复盘内容正确
[ ] 6. 金币余额计算无误
[ ] 7. 跨用户数据隔离有效
[ ] 8. AI API 降级兜底正常
[ ] 9. 小程序首页加载 < 3s
[ ] 10. 思维转换生成内容合格
```

| **P0 - 致命** | 小程序崩溃、数据丢失、安全漏洞 | 立即修复 |
| **P1 - 严重** | 核心功能不可用（无法创建任务、AI 不返回） | 24 小时内 |
| **P2 - 一般** | 功能异常但有替代方案（金币显示错误、排序问题） | 下个版本 |
| **P3 - 轻微** | UI 问题、文案优化、交互细节 | 排期修复 |
